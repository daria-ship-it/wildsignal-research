GEO Audit — Evaluation Methodology

Field guide · Wild Signal Agency July 2026

The rulebook the Wild Signal GEO Audit tool runs on: how it decides whether a web page is readable, trustworthy, and citable by AI search systems.

The core idea

AI systems can only cite what they can (1) reach, (2) parse, (3) understand as structured entities, and (4) trust as a substantive, current answer. The tool scores a page against those four things, in that order, because they build on each other: perfect content is worthless if a crawler is blocked at the door.

Each page is scored on four domains, each on a 1–5 scale. The overall GEO Readiness Score is the plain average of the four, rounded to one decimal.

Domain What it answers Weight in overall
1 · Crawlability & Technical Access Can an AI crawler reach and read this page at all? 25%
2 · Schema & Structured Data Can it interpret the page as typed entities, not just text? 25%
3 · Content Architecture Is the page structured so answers can be extracted and placed in a topic cluster? 25%
4 · Content Quality (GEO Writing) Is the content written to be extracted, trusted, and cited? 25%

The four are weighted equally on purpose. A page that is flawless on content but blocks GPTBot is not a good page for AI citation, and the equal weighting keeps any single failure from being hidden by strengths elsewhere.

How scoring works (the mechanics)

Every domain uses the same underlying method, so scores are comparable across pages and repeatable across runs.

  1. Point accumulation. Each check inside a domain earns a fraction of that domain's point budget (some checks are worth more than others — e.g. a single H1 is worth more than a breadcrumb). The tool sums the earned points.
  2. Ratio to 1–5. Earned ÷ total is mapped onto the 1–5 scale: score = round(1 + ratio × 4). So 0% of checks = 1, 100% = 5.
  3. Critical caps override the ratio. Certain failures are disqualifying no matter how good everything else is. These cap the domain score regardless of points earned (listed per domain below). This is why a page can have lots of green checks and still score a 2 — one blocking failure caps it.

Every finding is evidence-based. The tool reports the actual value it found (the HTTP status, the exact blocked bots, the word count, the specific skipped heading levels), never an estimate. If it couldn't measure something, it says so rather than guessing.

Finding statuses: each check is marked pass (green), warn (amber), or fail (red). These drive the icons and colored numbers in the report — status is shown through color on text and icons only.

What the tool fetches

For a single-page audit, the tool retrieves, server-side (no JavaScript execution):

  • The target page — raw HTML, up to 5 MB, 15-second timeout, with a realistic desktop browser User-Agent identifying as WildSignal-GEO-Audit/1.0.
  • /robots.txt, /sitemap.xml, /llms.txt at the same origin — best-effort, up to 400 KB each, 8-second timeout. A missing file is a finding, not an error.

Because it reads the raw HTML response (what a non-JS crawler sees), single-page applications that paint content with JavaScript will legitimately score low on "server-rendered content" — that reflects real AI-crawler behavior, not a tool limitation.

For a full-site or blog audit, the tool discovers pages sitemap-first (falling back to internal-link following), audits each page with the identical per-page logic, and rolls the scores up. Origin-level checks (robots.txt, sitemap, llms.txt, HTTPS) are evaluated once for the whole site. Depth is capped at 25 pages ("First 25") or 150 pages ("Entire site").

Domain 1 — Crawlability & Technical Access

Can an AI crawler reach and read this page? This is checked first because nothing downstream matters if the answer is no.

Checks and what earns points

Check Pass condition Notes
Page fetch HTTP 2xx Warns if response > 3s (crawl-budget threshold); reports redirects
robots.txt present File exists at origin Also parses it for the checks below
AI crawler access All five checked bots allowed on the page's path The single most important check in the domain
Sitemap referenced in robots.txt A Sitemap: directive is present Advertises the URL inventory to crawlers
XML sitemap /sitemap.xml returns 200 Reports whether it's an index and the <loc> count
llms.txt /llms.txt returns 200 Emerging convention; a warn (not fail) if absent
HTTPS & mixed content Served over HTTPS with no http:// resource refs HTTP-only is a critical fail
Canonical tag <link rel="canonical"> present Prevents citation signal splitting across URL variants
Server-rendered content Meaningful text in the raw HTML See JS-rendering rule below
URL cleanliness ≤ 2 query params, no session/tracking keys, path < 120 chars Stable URLs are better anchors for AI embeddings

The five AI crawlers checked

GPTBot (OpenAI), ClaudeBot (Anthropic), PerplexityBot (Perplexity), Google-Extended (Google's AI training/AIO control), and Googlebot. Robots rules are evaluated with Google-style longest-match logic against the specific page path — so a bot blocked only on /admin is not counted as blocked for a blog post.

JS-rendering rule

A page is flagged as a client-render risk when the raw HTML has fewer than 200 characters of visible text AND (more than 3 <script> tags OR an empty SPA root element like #root / #app / [data-reactroot]). That pattern means the content only exists after JavaScript runs — invisible to crawlers that don't execute JS.

Score caps (these override the point total)

  • Any of the five bots blocked on the path → score capped at 2.
  • A blanket Disallow: / for *, or all five AI bots blocked → score = 1 (the highest-impact fix on the site).
  • JS-rendering risk detected → score capped at 2.

Domain 2 — Schema & Structured Data

Can the AI interpret the page as typed entities — an Article, an Author, a Publisher — rather than inferring everything from raw text? Pages with schema see materially higher citation rates.

How schema is read

The tool parses every <script type="application/ld+json"> block, walking @graph arrays and nested entities (author, publisher, mainEntity, etc.) to collect all @types. It also detects legacy microdata (itemtype). Blocks that fail to parse as JSON are counted as parse errors — invalid schema is silently discarded by real consumers, so the tool treats it the same way.

Checks and what earns points

Check What earns the points
JSON-LD present Any parseable JSON-LD at all (the biggest single chunk of the budget)
Article schema Article / BlogPosting / NewsArticle / TechArticle, complete with headline, author, datePublished
FAQPage schema Present — makes Q&A machine-extractable
Organization schema Present; bonus for both logo and sameAs
Person schema (author) Present; bonus for sameAs links resolving the author to external profiles
BreadcrumbList Present
WebSite / WebPage Present — a typed container node
Media schema ImageObject and/or VideoObject
Schema breadth 3+ distinct types on the page
Schema validity All JSON-LD blocks parse cleanly

Article schema is treated as expected on editorial/blog pages but not required on pure product or landing pages.

Score caps

  • Zero usable structured data → score = 1 (AI has to infer entity, author, publisher, and content type from raw text).
  • Any JSON-LD block fails to parse → score capped at 3 (broken schema scores the same as no schema).

Domain 3 — Content Architecture

Is the page structured so an AI can extract answers section-by-section and understand where the page sits in a topic cluster? AI systems judge topical authority across a site, and the overwhelming majority of citations go to deep, well-structured pages rather than homepages.

Checks and thresholds

Check Pass threshold Why the threshold
Single H1 Exactly one <h1> 87% of cited pages use exactly one H1; zero or multiple splits the topic signal
Heading hierarchy No skipped levels (no H2 → H4 jumps) Clean nesting correlates with ~2.8x higher citation likelihood
Section structure (H2s) 3+ H2s = pass, 1–2 = warn, 0 = fail AI extracts answers per section; an unsegmented page offers nothing to lift
Internal linking 15+ internal links = pass, 6–14 = warn, < 6 = fail Thin interlinking leaves a page near-orphaned in the crawl graph
Anchor text quality < 5% generic anchors = pass; ≥ 15% = fail "Click here" / "read more" tell AI nothing about the destination
Content depth 800+ words = pass, 300–799 = warn, < 300 = fail Thin pages rarely survive the comprehensiveness filter
Breadcrumbs Visible breadcrumb nav OR BreadcrumbList schema Makes the page's place in the hierarchy explicit

Generic anchors detected: click here, read more, here, link, learn more, this page, more, see more, continue reading.

This domain has no hard score caps — it's a straight point ratio, because architecture problems are cumulative rather than single points of failure.

Domain 4 — Content Quality (GEO Writing Standards)

Is the content written to be extracted, trusted, and cited? This is the per-page application of Wild Signal's GEO writing standards, measured with text heuristics on the rendered copy.

Checks and thresholds

Check Pass threshold The standard behind it
Answer-first opening First paragraph is substantive (≥ 80 chars) and leads with a complete sentence 44.2% of citations come from the first 30% of a page
Question-based headings 3+ H2/H3s phrased as questions Question-form headings match how users prompt AI and double citation odds
Paragraph length Average ≤ 4 sentences per paragraph 2–4 self-contained sentences is optimal for extraction
Statistics & data density ≥ 1 numeric data point per 80 words Data-dense, entity-rich text is cited ~3x more than generic prose
FAQ section An FAQ heading OR FAQPage schema FAQ blocks double citation odds — the cheapest GEO win
Author byline (E-E-A-T) Author in schema, meta, or a visible byline E-E-A-T signals carry a +30.64% citation lift; 96% of AIO citations have strong E-E-A-T
Publish / update date Machine-readable date in schema, meta, or <time> Undated content forfeits the freshness signal
Content freshness ≤ 180 days = pass, ≤ 730 days = warn, older = fail 85% of AIO citations come from content under two years old
Meta description Present, 50–160 characters The summary snippet discovery systems read first
Non-promotional tone No superlative marketing language Promotional content is 26.19% less likely to be cited (informational only, lightly weighted)

Question-heading detection: a heading counts if it ends in "?" or starts with what/how/why/when/where/who/which/can/should/does/do/is/are/will. Superlatives flagged include best-in-class, world-class, cutting-edge, revolutionary, game-changing, industry-leading, unparalleled, seamlessly, effortlessly.

This domain also has no hard caps — it's a point ratio, since quality is a matter of degree.

From findings to recommendations

The tool doesn't just score — it prioritizes fixes. Every failed or sub-optimal check generates a recommendation carrying a severity and an internal impact weight. Across all four domains, recommendations are sorted by severity first, then by weight, and the top five surface as Top Priority Recommendations.

Severity Meaning Example triggers
Critical Disqualifying for AI citation; fix first AI bots blocked, HTTP-only, JS-only rendering, no schema, broken JSON-LD
High Major citation drag; high leverage Missing sitemap, no Organization schema, no FAQ, thin content, no author, stale content
Quick win Low-effort, meaningful upside Add llms.txt, add canonical, fix skipped heading levels, tighten meta description

Recommendations are written as concrete, executable instructions with the affected URL(s) — the same text also populates the "fix instructions for your AI coding assistant" section of the Markdown export, so a developer or a vibe-coding tool can act on them directly.

The research the thresholds are built on

The thresholds above aren't arbitrary — each maps to a documented GEO/AIO finding. The tool surfaces the relevant statistic in the finding detail so the client sees the "why," not just the "what."

  • 82.5% of AI citations go to deep, topic-specific pages — not homepages.
  • Pages with schema markup see 47% higher citation rates; 3+ types add ~13%.
  • Multimodal content with full schema sees up to a 317% citation lift.
  • 85% of AI Overview citations come from content published in the last two years.
  • Content not refreshed quarterly is 3x more likely to lose citation positions.
  • Sequential heading hierarchy correlates with ~2.8x higher citation likelihood.
  • 87% of cited pages use a single H1.
  • FAQ sections double citation odds.
  • E-E-A-T signals carry a +30.64% citation lift; 96% of AIO citations have strong E-E-A-T.
  • Entity- and data-rich text is cited ~3x more than generic prose.
  • Promotional content is 26.19% less likely to be cited.
  • 44.2% of citations are pulled from the first 30% of a page.

Known limits (state these to clients)

  • Single-page, raw HTML. No JavaScript is executed. SPAs score low on server-rendered content by design — this mirrors real crawler behavior.
  • Heuristic content checks. Answer-first, paragraph length, and stat density are text heuristics, not editorial judgment. They flag patterns; a human still reads the page.
  • On-page and origin-file signals only. This tool does not measure off-site entity authority (Knowledge Panel, Wikipedia, backlinks, earned media) or true Core Web Vitals — it uses response time as a proxy. Those live in the full manual audit.
  • Site scans sample, not exhaust. "Entire site" is sitemap-first and capped at 150 pages; without a sitemap it follows internal links two levels deep and may miss deep pages.
  • Some origins block datacenter IPs (403), which the tool reports rather than scoring blindly.
